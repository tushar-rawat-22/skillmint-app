# Contributing to SkillMint

SkillMint is currently a controlled public beta. The repository is public for transparency and feedback, but external source-code contributions are not generally being accepted yet.

The most useful contributions right now are reproducible bug reports, accessibility findings, security reports, and product feedback grounded in real use.

## Before opening an issue

- Check whether the problem is already reported.
- Reproduce it against the current public beta when possible.
- Remove names, email addresses, resume text, job-description text, account details, private screenshots, and other personal information.
- Use synthetic examples when a reproduction needs sample resume or career data.

Security vulnerabilities should follow `SECURITY.md` rather than a public issue.

## Bug reports

Include the page or workflow, expected behavior, actual behavior, browser/device details when relevant, and the smallest reproducible sequence. Screenshots are useful only when they contain no private information.

## Product feedback

Describe the task you were trying to complete, where you became uncertain or blocked, and what you expected SkillMint to make clearer. Preference alone is weaker evidence than a concrete failure or repeated point of confusion.

## Pull requests

Please do not open unsolicited implementation PRs unless a maintainer has asked for one. If a code contribution is coordinated, keep it narrowly scoped and follow the existing pull request template and repository verification contracts.

No contribution or public-repository status changes the licensing rights of this codebase. The repository currently has no open-source license.
